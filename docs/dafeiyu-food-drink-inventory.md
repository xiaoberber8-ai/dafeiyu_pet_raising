## 三、缺口分析

### 缺口 1：零饮品（严重）

- **现状**：20 个进食动作中「喝」为 0。上游 106 个动作名里也没有任何饮品动作。
- **影响**：口渴/补水/提神/解暑/清洁度相关玩法**无动画可播**，只能借吃饭动作硬凑。
- **对策**：已补 6 条饮品提示词（白开水/咖啡/汽水/橙汁/热可可/珍珠奶茶）。

### 缺口 2：档 1 与档 3 共用 `ext_rice`

- **现状**：设计文档写 免费剩饭 → `ext_rice`，便当 → `ext_rice` / `ext_noodles`。
- **影响**：玩家吃免费剩饭和付费便当，**看到同一个动画**，付费缺乏正面反馈。
- **对策**：补「蛋炒饭」作为便当专属，与白饭视觉明显区分（有蛋有葱有火腿 vs 纯白）。

### 缺口 3：档 2 仅 1 个动作，会撞「重复厌倦」

- **现状**：档 2 只有 `ext_snack`。设计文档的衰减规则是连吃 4 次开始降效（下限 50%）。
- **影响**：玩家吃到第 4 次零食就触发衰减，且**没有别的零食可选**。

### 缺口 4：大餐缺乏"仪式感"层次

- **现状**：5 档大餐有 4 个动作（火锅/蟹/饺子/大零食），但都是 10 秒短平快。
- **影响**：设计文档说"高档食物买的是心情和仪式感"，10 秒演不出宴席感。
- **对策**：补「火锅丰盛版」（18 秒）、「生日蛋糕」（14 秒）。

## 六、命名规范（制作新 clip 时必须遵守）

### 6.1 clip id

| 规则 | 示例 |
|---|---|
| 全小写，`ext_` 前缀 | `ext_chips` |
| 单词连写不带下划线（多词也一样） | `roastedsweetpotato`、`bubbletea` |
| 不用中横线、不用空格 | ❌ `ext_bubble-tea` |
| 不与已有 112 个 id 重复 | — |

### 6.2 素材目录与文件

| 项 | 规范 | 依据 |
|---|---|---|
| 目录 | `assets/pet/<clip_id>/` | 现有 112 个目录均如此 |
| 文件名 | **3 位零填充**，从 `001` 起 | `ext_*` 类用裸编号 `001.webp`；核心类用 `<clip>_001.webp` |
| 尺寸 | **412 × 344** | 全库 26,580 帧一致 |
| 格式 | WebP 有损 `quality=68`，RGBA | `assetSource.webpQuality` |
| 帧率 | `frameMs: 42`（约 23.81fps） | 全库统一 |
| 裁切 | 共用 `[100, 0, 412, 344]` | `assetSource.crop` |

### 6.3 接入三处（缺一不生效）

1. `assets/pet/<clip_id>/` — 帧文件
2. `assets/pet-manifest.json` 的 `clips` — 加条目（`frames` / `frameMs` / `loop:false` / `source`）
3. `lib/actions.js` 的 `ACTIONS` 数组 — **不加会抛「未知动作」**
4. （可选）`idleMicroClips` — 不加则不会在待机时自动出现
